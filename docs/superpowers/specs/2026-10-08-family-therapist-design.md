# 家庭关系咨询空间：第一版设计

日期：2026-10-08（America/Los_Angeles）

状态：产品设计及本文已获 derek 确认，进入分阶段实施计划；尚未进入产品实现。

## 1. 目标与范围

第一版仅供一对夫妻使用。目标是帮助双方理解和认可彼此，形成自愿接受的相处方式；不以判定输赢、认错、让步或结束议题的数量衡量成功。允许尚未达成共识。

固定结构：

**丈夫 + Codex + Skill（本地 Therapist Assistant） → 同一个云端 AI Therapist ← 妻子 + Codex + Skill（本地 Therapist Assistant）**

没有额外的协调 Agent。云端 Therapist 同时负责咨询、保持议题聚焦和帮助形成共同理解。第一版不做多家庭注册、网页聊天、网页确认、邮件通知或其他聊天渠道集成。

AI 必须明确身份。“20 年经验”代表对成熟沟通和知识深度的期望，不能作为真实执业经历或疗效承诺。系统不对任何一方作心理诊断。

## 2. 本地 Therapist Assistant

本地 Codex + Skill 不只是摘要器或转发器。它先充分倾听，再通过追问帮助本人理解经历，形成足够完整的表达。

梳理包括：这一次发生的事情；本人直接观察到的内容；对对方意图的理解与不确定之处；当时与现在的感受；赋予事情的意义；希望被理解的需要；希望进一步讨论的问题。使用自然表达，不强制填表，不以篇幅长短评价完整度。

本地 Assistant 保留本人的声音，不制造动机、情绪、自我批评、让步或对另一方的认同。探索性解释只有在本人认可后才能代表本人发出。对私人梳理可以容纳联想与旧事，最终共同表达聚焦当前议题。

提交前展示完整原文，说明另一方也可见，由本人明确确认后发送。文字改变后须再次确认。未发送草稿和本地原始聊天不上传。提交前同步新消息；若新信息影响当前草稿，先让本人理解，再确认是否发送。

收到云端回复后，展示准确原文，帮助本人消化、表达认同或异议，形成下一次表达。不得自动代表本人继续咨询、同意共识或同意重开。

本人同意由受信任的本地 Skill 执行；API 能验证账号、操作与文字版本，不能独立证明本人确实阅读并同意。第一版不声称提供独立的人类确认认证。

## 3. 云端 Therapist 的工作方式与 Skill

### 3.1 每次运行的输入

- 当前 thread 的具体议题、状态及本轮输入截止位置。
- 双方正式表达、此前 Therapist 回复和仍待回应的问题。
- 带来源引用的当前理解摘要、共同点、差异和探索假设。
- 相关已确认共识及长期原则。

已 settled 的旧事默认提供结论，不自动加载整段旧争论来重新评价。用户仍可在网页阅读历史档案，但历史可查不等于允许重开咨询。

摘要是可追溯的工作上下文，不替代正式原文。需要具体细节时从相应消息读取。摘要和引用供双方查阅，不创建隐藏的人格定性档案，不保存模型隐藏推理。

### 3.2 咨询方法

Skill 定义目标、理解方法、回应策略、议题规则、纠错和适用边界。心理动力学、依恋和家庭系统等视角用于形成探索性问题，不把理论解释当成已经发生的事实。

每轮选择当前有帮助的动作：倾听、澄清、邀请另一方表达、区分体验与解释、探索相互影响的互动、提出可尝试的做法、整理共同理解。不是每次都给完整分析，不追求每轮得出解决方案。

仅收到一方表达时，可以回应感受和澄清问题；涉及双方关系的整体分析和建议，应听取双方后再开展。不因发言先后、长度或次数偏向某方。确认有新回复不意味着需要催促另一方。

允许双方纠正 Therapist。纠正后更新摘要和后续回应，不维护错误解释，不机械地对双方作对称批评。若后续一方未回复，不反复生成同一个追问。

适用边界：遇到现实危险、胁迫或紧急求助，不以促成一致或遵守旧结论阻止求助；允许任何一方停止参与。此类支持不授权自动向第三方披露内容。

### 3.3 输出

1. 给双方的正式回复。
2. 议题理解摘要及其来源位置。
3. 右栏共同点、待理解之处、探索假设的版本更新。
4. 需要时提出共识或结束议题的建议，等待双方操作。

只有客户端正式输入触发新的咨询处理；读取消息、导出、心跳、升级通知和 Therapist 自己写入的摘要不能递归触发咨询。收到确认或重开等操作时先由系统更新相应状态，只有出现需要咨询回应的实质变化才安排 Therapist，避免无限自对话。

## 4. Thread 与状态

一个共同空间包含多个 thread。一个 thread 对应一件具体事情，不按日期、登录、Codex 会话划分；同一问题可以持续多天。过于宽泛的题目须协助明确，标题不预先定责。

| 状态 | 含义 | 数量限制 |
| --- | --- | --- |
| pending | 已提出、尚待共同讨论，也可以是切换后仍未结束的旧议题 | 不设硬上限 |
| active | 当前共同聚焦的议题 | 最多 1 个 |
| settled | 双方确认结论，并明确同意该议题结束 | 不限 |

不设置 paused。暂时不交流不改变状态，不自动催促、同意或结案。open 只是 pending + active 的筛选条件。

无 active 时，一方可开启议题，Therapist 先接住表达并邀请另一方；有 active 时，新议题进入 pending，不同时开展第二场咨询。

切换已有讨论焦点需双方确认同一切换请求；原 active 回到 pending，目标 pending 变成 active。操作须在一次原子状态变更中完成。没有 active 时，历史 pending 的共同恢复也通过明确的选题操作完成，不能由心跳或模型擅自选择。

重开 settled 必须双方同意同一重开请求。重开后回到 pending，再安排成为 active；保留旧结论及重开历史，不自动挤掉已有 active。

确认一条观点与结束整个 thread 是不同动作。可在同一次本人确认中明确授权两件事，但系统不能从确认观点推断已同意结束。

## 5. 共识与旧事边界

### 5.1 两种层次

右栏“当前话题共识”由 Therapist 自动归纳，每条共同点同时关联双方的来源 message UUID。不以沉默或没有反对推断同意。待澄清差异与 Therapist 假设独立标记。归纳可以被纠正，每次修订留存版本。

正式共识分为共同空间级别的长期相处原则，以及具体 thread 的共同结论。只有双方明确确认同一版本的准确文字后才生效。任何文字修改都形成新版本，旧确认不能自动继承。

### 5.2 已 settled 的议题

默认只引用结论，不重审旧事。提醒可采用：“这件事我们已经一起达成了 XX 结论，我们尊重当时共同作出的决定。现在可以引用这个结论，但先不重新讨论这件事。”

任何一方、本人 Agent 或云端 Therapist 均不能单方面重开。不同意重开不被描述为不愿沟通，不反复劝说。未回复不代表同意。

后续是否履行约定是新的独立事件，可建新 thread，引用旧原则作为背景；不借此重新争论已结束的事件。仍然难过可以在本地或当前适当话题中被接住，不等于授权重开。共识不限制离开讨论或求助。

## 6. 消息、UUID 与同步协议

每条正式记录有永久 UUID。双方表达、Therapist 回复、thread 状态变化、共识提案与确认、自动归纳版本、升级通知都进入统一追加记录流，以 kind 区分。网页按类型展示，不把所有操作变成聊天气泡。

基础字段：message_id、space_id、可选 thread_id、kind、经服务器认证的 actor、created_at、内容或版本引用、服务器内部顺序。AI 输出记录所依据的输入截止 UUID、模型配置版本和 Therapist Skill 版本。

UUID 是身份，顺序由服务器提交时分配的单调递增序号决定；不比较 UUID 字符串或双方设备时间。正式记录不原地改写，更正追加并关联原记录。

读取范围支持整个共同空间与指定 thread，两者游标分别保存：

- 传 after_message_id：返回该记录之后的数据，游标对应记录不重复返回。
- 不传游标：从最早历史开始分页，全量读取不静默截断。
- 返回 next_after_message_id、has_more；一页成功落地后才推进本地游标。
- 无新消息时保持原游标；不存在、无权限或范围不匹配的游标返回明确错误。
- 全量同步固定一个读取上界，完成后从该位置继续增量，避免持续写入导致全量读永远不能完成。

客户端同一次发送使用同一个 UUID。服务器验证身份与内容；相同 UUID、相同主体和内容返回既有结果；内容或主体冲突拒绝覆盖，不泄露其他主体的信息。

API 能力：读取空间/thread 历史；读取当前状态；提交本人确认的表达；提出/确认共识；提出/确认切换或重开；提出/确认结案；获取认证后的档案与 Skill 更新包。所有写操作独立于网页，身份不能由请求体里自填的“丈夫/妻子”决定。

## 7. 云端执行与失败处理

正式输入与待处理任务可靠落库后才返回“已收到”。已接收、处理中、已回复、失败为不同状态，不用 HTTP 成功代替咨询已完成。

同一 active thread 的咨询任务串行处理；一次运行固定输入截止位置。运行期间到达的新表达进入后续处理，不悄悄改变已经发出的回应依据。输出提交检查输入版本；若 thread 已切换、settled 或相关共识发生变化，旧输出不能越过新状态直接发表。

任务有持久状态、唯一运行标识、有限期执行占用和重试记录。进程终止后任务可恢复。允许模型调用在故障恢复时被重复执行，但同一任务的正式结果只能提交一次；不承诺上游模型调用或费用绝对一次。

临时失败保留输入与任务，展示实际状态。后台处理必须不依赖网页、任何一方 Codex 或每小时客户端心跳保持在线。不能用请求结束后的临时内存任务假装持久后台处理。

## 8. 本地初始化、每小时心跳与自动升级

### 8.1 初始化与消息同步

首次完成身份配置和历史同步后，安装或复用本地每小时心跳任务。重复运行 Skill 不创建重复任务。任务保存应核对状态，并执行一次受控同步验证；任务建立不等于定时运行已被证明。

每小时按空间游标读取全部增量分页。开始主动咨询、准备发送、等待本轮回应时额外及时同步，无需等待下个小时。多个触发共享同步锁，防止游标回退、重复通知与并发安装。

无变化保持安静。新表达、Therapist 回复及需本人确认的操作按需提醒，不重复提醒。心跳不发送咨询表达、不确认共识、不批准重开。

离线或休眠时不保证整点运行；恢复后从既有 UUID 补齐。短暂失败保留进度，身份失效或持续错误需要本人处理时通知。任务提示不包含秘密，凭证由本地安全配置读取。

### 8.2 云端通知升级

由 derek 维护发布版本。云端发布带 UUID 的升级通知，包含目标版本、更新包地址、内容校验信息和简要说明。心跳随增量接收通知，不额外轮询独立版本接口。首次全量同步根据发布顺序确定当前发布目标；版本不是按字符串大小比较。

本地收到尚未安装的目标版本后自动下载、做文件完整性与安装兼容性检查、原子切换并记录结果。重复通知跳过。失败保留可用版本，将目标版本记为待重试；消息游标与安装结果分别保存，已读通知不能导致放弃升级。

删除更新内容的语义审查及要求双方批准规则变更的升级治理流程；不判断新版是否改变约定，不添加人工升级确认。技术来源与完整性校验保留，凭证不发送到任意更新链接。

正在梳理或待本人确认时，更新先准备，在当前操作结束后切换；升级不自动发送草稿。普通升级成功保持安静，需要本人处理的失败或显著使用方式变化才提示。

### 8.3 本地文件职责

- 共享 Skill：咨询辅助方法、API 协议、同步与升级规则，随发布更新。
- 个性化辅助方法：根据本人明确反馈自动更新，保留原因及版本，不随共享包覆盖。
- 本地私密状态：本地咨询上下文、未发草稿、游标、通知进度、待升级记录，独立保存。

普通咨询消息不被当作升级命令；识别升级依据服务器授权的系统记录类型。不得把对另一方的推测固化为本地人物结论。个性化内容不上传到共同空间或混入共享发布包。

## 9. 网站与文件

网站三个区域：当前咨询、共同原则与共识、对话档案。没有发言、编辑共识或确认入口。只有两位成员可查看、下载；后台管理员能力不作为第三个咨询参与人。

当前咨询展示完整、经本人确认的成熟表达及 Therapist 原始回复。右栏展示有来源的自动共同点、待理解部分、探索假设及正式结论，避免把聊天气泡的短句示例当成本地辅助方法。

正式记录以数据库事件流为权威；持续生成每个 thread 的 Markdown 和 JSONL 档案，并独立生成共同原则与共识文件。文件包括来源、版本、确认与重开记录，不含本地私密聊天或模型隐藏推理。网页摘要不替代原文。

文件带导出截止 UUID/版本，生成后校验再公布为当前档案。写入和文件生成不是同一原子事务，未更新完成时明确显示档案截止位置，不能把旧文件宣称为最新。失败可从正式流重新生成，不重复发送咨询消息。

鉴权作用于页面、读取 API、下载、写入和更新包；不公开对象存储文件地址。机密、真实咨询数据和个人辅助文件不提交到源码仓库。

## 10. Sites 能力核实与部署前置条件

本次只读核对了已安装 Sites 资料，未创建 Site、云端数据库、定时任务或模型调用。

已确认的资料能力：Sites 支持服务端 Worker 和 HTTP 外连；D1 用于结构化数据，R2 用于文件；ChatGPT 登录可提供 Site 内稳定身份，仍需应用成员校验；非用户服务访问不自动提供丈夫/妻子的成员身份，须另行认证主体；原生访问工具支持自定义访问名单，但外部访客可用性需真实 Site 核实。

部署前必须完成以下验证，结果不足则停在验证阶段，不宣称端到端产品完成：

1. **持久后台执行**：现有 Sites 资料没有证明原生提供满足本设计的持久任务运行器。实施计划首先验证受支持的后台方案；若 Sites 不能承担，提出独立云端运行器的具体方案供确认，保留同一 Therapist 角色和 API，不擅自部署到已有共享服务器。
2. **模型调用**：模型提供方、模型版本及凭证尚未选定。实施前明确配置并验证真实调用。若选择 OpenAI，遵循 Sites 指定的 OpenAI Developers 密钥流程；不把本地 Codex 订阅或浏览器登录视为云端 API 凭证，不打印或写入源码。
3. **双方访问**：核实 Site 支持第二位成员身份访问，实际配置前取得准确账号信息；不猜配偶邮箱、不擅自发送邀请、不为绕过权限而公开网站。
4. **本地无人值守访问**：两边心跳均须能从安全配置取得有效平台访问和各自成员凭证；不依赖当前交互会话临时授权。恢复或撤销凭证需明确错误状态。

以上是明确的部署验收前置条件，不是已经完成的能力。部署平台选择不会改变已确认的产品规则；新增运行资源或更改访问方式须以具体方案确认。

资料来源（本机已安装插件）：Sites SKILL.md、references/identity-and-secrets.md、references/storage.md、references/recurring-updates.md，以及 sites_update_site_access 工具契约。未验证的原生队列能力不作为依据。

## 11. 验收

使用虚构完整咨询案例进行本地 Assistant 与云端 Therapist 的行为评估，不上传真实夫妻私密材料作为测试数据。通信、权限、状态转换和恢复另做确定性测试。

| 场景 | 通过条件 |
| --- | --- |
| 本地表达分散、情绪强、夹带旧事 | 充分倾听并梳理完整表达，保留本人意思，不擅自发送、不要求虚假让步 |
| 本人确认后发送 | 保存文字与确认版本一致，不包含本地私聊 |
| 只收到一方表达 | 接住感受、澄清问题，不替另一方推断动机或生成双方共识 |
| 双方观点相近但不相同 | 共识有双方原文依据，差异与假设不混入共同认定 |
| 用户纠正 AI | 明确修正摘要和后续理解，并保留来源 |
| 单方确认、不同版本确认、沉默 | 不形成正式共识、不 settled |
| 确认单条共识 | 不自动结束整个 thread |
| 单方翻旧账与新事件 | 旧事只引用，新事件独立讨论；重开必须双方同意 |
| 并发选题、切换、结案 | active 最多一个；状态和确认一致，保留完整历史 |
| 并发消息与运行中状态变化 | 回复有固定输入边界，过期输出不突破已更新状态 |
