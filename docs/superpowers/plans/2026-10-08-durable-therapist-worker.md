# Durable Therapist job execution Implementation Plan

> **For agentic workers:** Use subagent-driven-development. GPT-6 Luna medium develops; root personally reviews and accepts.

**Goal:** Connect durable accepted expressions to the real Responses tool loop and validated atomic publication, with lease recovery and stale-state refusal independent of a browser.

**Architecture:** Capture the input's thread version atomically at intake. A server worker claims one task per thread, freezes scope/model/Skill/output contract, saves each Responses checkpoint under a fenced lease, and publishes one reply plus automatic understanding only when the current thread/principles still match. This source task does not claim hosted scheduling or real provider generation.

**Tech Stack:** Existing D1 transactions, Responses loop, five query tools, output validator, Web Crypto hashes/UUIDs, actual SQLite integration tests with injected provider.

## Files and behavior

- Add `src/server/therapist-worker.mjs`: `runNextTherapistTask({db,space_id,config,request,now,lease_ms})`. `config` is trusted `{model,skill_version,instructions,output_schema,max_tool_calls}`; never from HTTP JSON. The worker derives two member identities from current registry and binds consultation thread/snapshot; only read tools reach the model.
- Extend therapist_tasks additively/generated migration: input_thread_seq (default0 means uncaptured, explicitly obsolete), status queued/running/failed/obsolete/completed, lease_id/lease_expires_at, run_snapshot_seq, run_config_json, checkpoint_json, stable reply/understanding/candidate UUIDs, safe last_error metadata. Partial unique index prevents two running tasks for the same space/thread. Preserve existing data; no runtime schema creation or hidden backfill.
- Update intake task insertion to capture the verified `expected_thread_seq` in the same atomic batch. Receipt accepts defined current task statuses, preserves immutable input identity/text/time, and clearly distinguishes accepted record from task execution status.
- Claim SQL and all checkpoint/finish statements require the current lease ID. Expired running task can be reclaimed; old owner can neither save a checkpoint nor publish. Current membership/current active thread and original resource version are checked before execution and again atomically at publish. Pending/settled, changed thread/consensus/principles, missing source version or removed member => obsolete, no model reply.
- A run captures current space snapshot at claim, including prior replies and accepted inputs already present. Preserve the same snapshot/config across recovery. Task bound to original accepted source version; no future expression after run snapshot joins that output. On successful final commit, mark other queued tasks for this same thread/source version whose input sequence is within that run snapshot as covered/completed by the leader run (nullable covered_by field), preventing a duplicate reply to already-included input. Newer inputs remain queued. Only the leader is running, preserving the partial unique index. Do not make another server's message/identity or a client-supplied actor authoritative.
- Use `runTherapistTurn` with injected provider and D1 executor. Validate output using server-retrieved formal `member_expression` metadata at frozen scope. Common points and candidates need both real members' citations. No semantic keyword heuristics.
- Persist raw orchestration checkpoints only in private job state, never public archives or conversation messages. Only validated reply/understanding/candidate are public formal records, with source UUIDs, model/Skill version and run boundary. Candidate stays unconfirmed and cannot invoke discussion approval.
- Final D1 batch must fence lease and check latest active thread version plus frozen global agreements/principles before any event insert. Record stable predefined UUIDs and completion together; repeated finish/recovery never duplicates business records. Forced write failure rolls back status/output together. Error cannot become an empty success or fabricated reply.
- Add `src/server/openai-responses.mjs`: fixed official endpoint, trusted server API Key (not stored in checkpoint/config or returned), JSON request/response with bounded timeout/bytes, redirect refusal, safe provider status/code/request-ID error without key or prompt logging. No real call in this task (organization credits exhausted).
- Add server config bundling cloud SKILL.md and its method reference through Vite raw imports, explicit version and configured model; model API Key stays in env only. Optional manual drain route uses member Token, scope bound to its space and no body configuration; it proves only requested execution, not unattended triggering. Missing env is explicit503 with no false task completion.
- UI view gains safe latest task status for selected thread: queued means expression saved/waiting, running means processing, failed means reply incomplete, obsolete means state changed/no reply published. Existing response cards stay only actual replies; no fake clinician output.
- Tests `tests/site/therapist-worker.test.mjs` plus provider adapter tests: actual migrations/transactions, two read tools then validated output publication; one-party no common point; unknown citation rejected; checkpoint crash-like recovery; expired lease and stale owner; stale status/agreement/version prevents publication; output transaction rollback; exact UUID final idempotence; key never serialized; provider quota/error remains explicit failure.
