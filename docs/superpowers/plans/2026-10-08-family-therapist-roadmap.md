# 家庭关系咨询系统 Implementation Plan：实施总览

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将已确认的夫妻双方本地 Therapist Assistant、云端 Therapist、只读网站及自动同步升级交付为可验证的完整系统。

**Architecture:** 两个本地 Codex 通过各自身份连接同一个云端 Therapist。正式记录采用 UUID 与服务器顺序；确认和 thread 状态由应用管理，咨询方法由云端 Skill 管理。Sites 承载网站/API/存储，可靠后台执行能力必须先验证。

**Tech Stack:** 核心规则采用可在 Node 与 Worker 使用的 JavaScript ES modules，Node 内置 test/assert；Sites 网站使用其保留的 Vinext/React starter、D1/R2。模型提供方和可靠运行器通过阶段 B 的证据决定，不假定已有账号或资源。

## 计划边界

已批准设计：`docs/superpowers/specs/2026-10-08-family-therapist-design.md`。

拆成四个可独立验收的交付阶段。本文是全系统路线与覆盖清单；配套 A 计划包含逐项代码和测试，可直接执行。B/C/D 的生产代码计划在 A 的协议与 B 的部署能力核实后展开，不将路线图冒充已完整编写的逐文件生产实现计划。

阶段 A 不部署、不调用模型、不设置真实自动化。其内存数据是纯函数测试输入，不是生产数据库或消息队列。

## 阶段 A：消息与共同讨论规则

- [ ] 执行 `2026-10-08-family-therapist-protocol.md`。
- [ ] 测试 UUID 游标排除本条、空结果、固定快照分页、无效游标、时间乱序不影响服务器顺序。
- [ ] 测试至多一个 active、单方确认不生效、内容不同不能共用确认、确认共识不自动 settled、切换及重开保持历史。
- [ ] 冻结纯函数契约，提交可复现测试证据。

完成定义：独立的可执行协议规则包与回归测试。不能称为 API 已部署或真实身份已验证。

## 阶段 B：云端咨询与可靠运行

### B0 先核实四项依赖

- [ ] 检查真实 Sites 的访问能力。必须先按 Sites 工作流创建一次并持久化其 ID，再读取 `get_site`；不重复注册、不改变成公开站点。
- [ ] 核实后台任务是否可以在两边 Codex 和网页均关闭时继续完成并在执行中断后恢复。仅有 `waitUntil` 或 scheduled task 声明不能作为证据。
- [ ] 如平台无法支持，提交独立运行器的具体主机、数据流、权限、费用与恢复方案给 derek 确认，不擅自占用共享生产服务。
- [ ] 选择明确模型配置并按平台规定完成凭证配置。OpenAI 路径需要可用的 OpenAI Developers 插件及其密钥流程；不把 Codex 登录当 API Key。
- [ ] 获得第二位成员的准确账号，验证平台可访问和应用成员身份分别成立。若平台邀请会发信，应在实际发出前取得相应授权。
- [ ] 验证无人值守请求具备平台访问与成员权限两个层次，服务令牌不能冒充另一方。

将结果写入 `docs/operations/runtime-decision.md`：每项明确 supported/blocked、证据时间和来源、采用方案以及读回结果，不记录秘密。

### B1 持久 API 与 Therapist

- [ ] 基于 A 的契约写生产数据库与 API 逐文件计划；在 D1 或已批准数据库事务中同时保存输入和任务，并在数据库约束中保证唯一 UUID 与单 active。
- [ ] API 身份由认证取得，拒绝请求体 actor 覆盖；相同 UUID 内容一致返回原收据，冲突拒绝；记录授权全文与内容版本。
- [ ] Thread 所有变更、正式共识与确认进入统一追加流；API 的并发测试必须用真实存储适配器，不能仅重跑纯函数。
- [ ] 运行器固定输入截止位置并串行处理。杀停测试只针对测试进程；证明恢复、过期占用回收和结果唯一提交。
- [ ] 输入中 thread 状态或共识改变后，迟到的模型输出不得越过当前状态发表。消息与输出均保留来源与 Skill/模型版本。
- [ ] 编写云端 Skill；保持默认旧事只加载已确认结论，不因为摘要将历史推测变成事实。
- [ ] 以同一组虚构案例验证单方表达、误读纠正、互动探索、共识差异、拒绝重开和当前安全求助；评分不能靠词语命中或模型自称完成。
- [ ] 检查自动归纳的引用确实来自双方正式表达；无依据的共同点不进入右栏，解析失败保存为失败状态而非成功空结果。

完成定义：真实输入可产生可追溯的模型回复，并在客户端关闭及后台中断后保持可靠；权限、数据库并发与咨询案例均有证据。模型有限案例评估不等于临床有效性证明。

## 阶段 C：只读网站与文件

- [ ] 编写已保留 Sites starter 下的页面逐文件计划；导航为当前咨询、共同原则与共识、对话档案，不提供发言或确认入口。
- [ ] 使用完整虚构表达验收排版，明确区分原文、AI 假设、自动共识与正式共识。
- [ ] 为每个 thread 生成 Markdown/JSONL，单独生成原则与共识文件。对象存储带截止 UUID；完成校验后才公布当前指针。
- [ ] 检验档案落后、生成失败和重试时页面正确显示截止位置；不能将已收到消息误显示为已包含在最新文件。
- [ ] 验证匿名、第三方、另一成员、无效下载目标和对象 URL 不泄露数据；正式页面只读不等于后端可省略授权。
- [ ] 桌面与窄屏检查三个页面：空数据、pending 列表、active 全文、等待 Therapist、失败、无共识、共识纠正、settled、重开、长历史分页及文件状态。
- [ ] 使用 Sites source helper 同步、打包与部署，记录源码提交/版本/部署状态；不把本地预览当生产。

完成定义：正式页面和文件来自同一持久流，两位成员可读取，其他主体不可访问；实际部署成功与浏览器行为分别报告。

## 阶段 D：本地 Skill、每小时心跳与升级

- [ ] 编写本地 Skill 与客户端逐文件计划，以 B 的实际 API 和凭证流程为依据，不虚构安装地址。
- [ ] 本地 Assistant 先听后问，完整表达由本人确认；自动化只能同步与升级，不能代为表态。
- [ ] 状态目录与共享安装目录分离，保存个人方法、草稿、游标、通知进度和升级待重试状态；机密不进入 Skill 或任务 prompt。
- [ ] 为主动使用、发言前检查与小时心跳提供同一个同步器和锁；落盘后推进游标，去重通知。
- [ ] 初始化先查看实际既有自动化，复用匹配任务，缺失才按 Codex heartbeat 工具建立每小时任务；保留静默/按需通知意图，读回启用状态。
- [ ] 云端系统类型通知提供版本、包地址、校验信息和说明；本地自动下载、技术校验、原子切换，失败保持当前版本并重试。
- [ ] 不加入更新语义审查、规则变更的双方升级审批或每次安装确认。个人上下文不被包覆盖，进行中的确认不被新版中断。
- [ ] 以虚构草稿测试两次初始化、重复/并发心跳、离线恢复、安装中断、已读后安装失败、通知重试、静默无变更和人格推测不固化。
- [ ] 每位成员在其自己的设备验证安装与小时任务。只能证明 derek 一侧时明确另一侧未验收，不远程推断已经安装。

完成定义：双方真实本地安装可以完成一次确认发送、接收回复、一次小时同步以及一次可恢复升级；任何被本地环境阻止的无人值守运行须明确报告。
