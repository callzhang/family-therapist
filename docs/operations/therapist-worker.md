# Durable Therapist worker

`POST /api/therapist/drain` manually asks the service to process at most one accepted expression in the authenticated member's current space. The request has no body. The member identity and space come from that member's Bearer token; model, instructions, schema, and tool budget come from server configuration. A response reports a task state only. A `completed` response means the service transactionally stored one validated Therapist reply and one automatic understanding record; it does not mean either member accepted a proposal.

The worker leases one task per thread. It pins the original active-thread version, current two-member registry, confirmed global principles, bounded server configuration, and the message snapshot before calling the provider. Read tools use that frozen snapshot. The worker saves each orchestration checkpoint while it owns an unexpired lease. A takeover can resume that checkpoint under the same run identity; the previous lease owner cannot save or publish. Before publication, the worker checks that the active thread, both member identities, and confirmed global principles still match. It then inserts the reply, understanding, and covered-input statuses in one D1 batch. A failure rolls back the public records and completion status together.

A process can stop after the provider has generated a response but before D1 stores that response checkpoint. Recovery may then repeat a provider request and its billing. Stable task UUIDs and the final D1 transaction prevent duplicate public business records; they cannot guarantee exactly-once provider billing.

Set `THERAPIST_MODEL` to an explicitly selected model available to the configured OpenAI API account, and configure `OPENAI_API_KEY` through the hosting provider's server-side secret store. The provider adapter sends to the fixed OpenAI Responses endpoint, refuses redirects, bounds response size and duration, and returns only status, a safe error code, and a validated request ID on provider errors. Neither credential is stored in task configuration or checkpoints. Do not put either setting in request JSON, source control, browser storage, or a shared member token.

`skills/cloud-therapist/SKILL.md` and its consultation-method reference are bundled into the server instructions. Bump `CLOUD_THERAPIST_SKILL_VERSION` when those instructions change so each run records the version it used.

`GET /api/view` includes the latest task state for the selected thread. The member page translates `queued`, `running`, `failed`, `obsolete`, and `completed` into explicit status text. Receipts continue to preserve the original expression, UUID, and creation time while returning the current task status.

This worker has an explicit manual trigger. No scheduled or unattended trigger is installed by this change. The configured production API model and secret, production D1 migration, actual hosted request, and browser-visible production result remain separate deployment checks. This implementation was verified with injected provider responses against real SQLite transactions; it does not claim a real provider response or a hosted business outcome.
