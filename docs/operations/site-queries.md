# Site query adapter operations

`sites/family-therapist/src/server/queries.mjs` exports `createQueryExecutor(db)`. Its executor accepts only the five existing read tools and uses parameterized D1 statements. Call it with a server-built scope containing `actor_id`, `space_id`, `snapshot_seq`, and `consultation_thread_id`. The model tool arguments must never supply or override these fields.

Before any thread, message, agreement, or cursor lookup, the adapter requires a `members` row matching `(space_id, actor_id)`. The authenticated request layer must map the signed-in identity to the canonical `members.user_id`, derive the space from trusted server state, and reject missing or ambiguous mappings. Never accept those identifiers from model arguments or client-controlled query parameters.

The default `purpose` is `therapist`: transcript reads are limited to `consultation_thread_id` and stop when that thread's latest snapshot version is settled. The trusted application layer may explicitly set `purpose: 'member_view'` for an authenticated shared-space member viewing their own workspace; membership remains mandatory, but that purpose permits reading other member-visible threads and settled transcripts. This field is server-owned and must not be reachable from model tool arguments.

Every read is bounded by `snapshot_seq`. Thread and agreement versions are selected at the latest anchor sequence at or before the snapshot. Message sequence is the timeline cursor; public cursors remain UUIDs and are exclusive. Lists return stable sequence and UUID ordering, a capped page, `has_more`, `next_after_id`, and the snapshot used. `next_after_id` always names the final returned UUID, including the last page; an empty page preserves the supplied cursor so incremental clients can safely keep their boundary. Invalid stored message JSON fails the read explicitly.

Production integration must bind the actual D1 database as `DB` and R2 bucket as `BUCKET` in the Site hosting configuration, run the generated D1 migration through the controlled deployment workflow, and verify the resulting schema before routing requests. This task only generated and inspected the migration; it did not apply hosted migrations, create real participant rows, or connect the adapter to the authenticated request route. Keep role authorization, identity mapping, snapshot issuance, and the distinction between therapist and member-view purpose in trusted server code. Do not expose arbitrary SQL, local filesystem data, or storage credentials through the query executor.
