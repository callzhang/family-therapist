# 初始化、同步与议题操作

此文记录已批准设计中的本地操作要求，不代表所需 API、账号认证、客户端或自动化已经实现。

## 初始化与每小时 heartbeat

首次初始化应在实际认证的传输配置与端点已验证后进行：识别本人所属空间与成员权限，全量分页同步正式记录并成功落盘，再保存空间级和 thread 级游标。草稿、私人笔记、个性化偏好、通知去重进度、更新器状态都属于个人本地状态，不放入共享同步或云端记录。

初始化先检查当前账号下已有的 Codex heartbeat 自动化，依据任务内容与目标空间识别是否已有匹配任务。若已有，则复用并核对启用状态和静默偏好；没有匹配任务时，只有在认证传输配置确实可用时才建立每小时 heartbeat。重复初始化不得创建重复任务。设置或复用之后读取实际任务状态；没有读回启用状态的证据时不得声称已安装或会运行。

heartbeat 只同步和处理系统升级，不代替本人表达。无变化时保持安静；有新的正式表达、Therapist 回复或需要本人处理的状态时按需提醒，不重复提醒。它不发送草稿、不确认共识、不切换或结束议题、不批准重开。休眠或离线期间不承诺准点运行；恢复后按已保存游标补齐。

本地客户端代码和 CLI 已提供，使用方法见 [本地客户端运行说明](../../../docs/operations/local-client.md)。实际端点、Sites 外层访问凭证和本地成员 Token 仍须由维护者在私密文件中配置，并对目标部署做读回验证。缺少任何配置时，不创建定时任务，也不模拟同步成功。当前实现不创建或核验 heartbeat，也不提供 Skill 自动升级器。

## 同步与离线发送

主动继续咨询、切换议题或准备发送前都要先及时拉取增量。若分页、落盘或身份检查失败，保留旧游标，明确报告最后一次成功同步位置及失败原因，不把旧状态当成当前事实。游标仅在该页正式记录已成功落盘后推进。

发送前若无法确认网络、认证或服务端收据，明确告知本人“尚未确认是否送达”。保留该版本和发送结果的不确定状态，先通过真实协议核对 UUID 收据；若无法核对，停下并说明需要恢复连接或查明结果。不要擅自换 UUID 重发，以免重复表达。客户端包含 UUID 收据读取方法；若结果不确定，应使用原 UUID 查询收据并读回核验，不能盲目改 UUID 重发。

## 议题状态与旧事

共同空间只允许一个 active thread，其他未结束议题为 pending。没有 active 时，本人可提出新议题；若存在 active，新议题留在 pending。共同切换需双方确认同一切换请求，原 active 返回 pending，目标 pending 成为 active。心跳和 Therapist 都不得代替选题。

结案与对某条观点的认可不同。settled 议题只引用正式共同结论，不加载旧争论重新分析。后续履约行为是独立新事件，可建立新议题并引用旧结论。旧议题重开需双方同意同一请求；一方拒绝或未答复都不是不愿沟通，也不代表同意。

## 自动更新

只把认证消息流中的系统升级记录当作更新指令，不从普通对话文本推断升级命令。按更新通知中的授权来源、目标版本和内容校验信息执行技术下载与完整性检查；技术校验通过后才切换共享 Skill。不能从版本号词典序推断先后，也不能猜测包地址或绕过校验。

共享更新不得覆盖个人草稿、个人上下文、游标、通知记录或偏好。咨询表达正在编辑或等待确认时，保留原版本与确认状态；更新不得替换待确认的内容，也不得自动提交。更新后只在需本人处理的失败或明显使用变化时提醒。当前未实现升级 API、包格式或安装器，因此只能说明边界，不能声称自动更新已实现。
