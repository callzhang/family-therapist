# 初始化、同步与议题操作

此文记录已批准设计中的本地操作要求，不代表所需 API、账号认证、客户端或自动化已经实现。

## 初始化与每小时 heartbeat

首次初始化应在实际认证的传输配置与端点已验证后进行：识别本人所属空间与成员权限，全量分页同步正式记录并成功落盘，再保存空间级和 thread 级游标。草稿、私人笔记、个性化偏好、通知去重进度、更新器状态都属于个人本地状态，不放入共享同步或云端记录。

初始化先检查当前账号下已有的 Codex heartbeat 自动化，依据任务内容与目标空间识别是否已有匹配任务。若已有，则复用并核对启用状态和静默偏好；没有匹配任务时，只有在认证传输配置确实可用时才建立每小时 heartbeat。重复初始化不得创建重复任务。设置或复用之后读取实际任务状态；没有读回启用状态的证据时不得声称已安装或会运行。

heartbeat 只同步正式记录并检查独立 release notice，不代替本人表达。无变化时保持安静；有新的正式表达、Therapist 回复或需要本人处理的状态时按需提醒，不重复提醒。它不发送草稿、不确认共识、不切换或结束议题、不批准重开。休眠或离线期间不承诺准点运行；恢复后按已保存游标补齐。

本地客户端使用方式：在项目本地运行 `node scripts/local-therapist-client.mjs sync-and-update <member.json> <connection.json> <private-state-dir> <absolute-skill-install-dir>`。实际成员文件、连接文件、同步目录和 Skill 安装目录必须由维护者在本地私密配置；不要把这些路径或凭证写入共享 Skill。端点、Sites 外层访问凭证和本地成员 Token 仍须配置，并对目标部署做读回验证。已有 heartbeat 应每小时及每次进入咨询前调用此命令；命令本身不创建或调度 heartbeat。若本地草稿或表达正等待本人确认，使用 `--consultation-busy` 暂存更新；本人完成当前操作后再次同步并更新才切换当前版本。

## 同步与离线发送

主动继续咨询、切换议题或准备发送前都要先及时拉取增量。若分页、落盘或身份检查失败，保留旧游标，明确报告最后一次成功同步位置及失败原因，不把旧状态当成当前事实。游标仅在该页正式记录已成功落盘后推进。

发送前若无法确认网络、认证或服务端收据，明确告知本人“尚未确认是否送达”。保留该版本和发送结果的不确定状态，先通过真实协议核对 UUID 收据；若无法核对，停下并说明需要恢复连接或查明结果。不要擅自换 UUID 重发，以免重复表达。客户端包含 UUID 收据读取方法；若结果不确定，应使用原 UUID 查询收据并读回核验，不能盲目改 UUID 重发。

已确认表达的提交收据若显示任务为 `queued`，只代表表达已保存并排队。具备已配置的本地客户端时，可在本人确认该表达之后调用 `processTherapist()`，手动处理队列中的一个任务；这只是处理既有表达，不是新表达，也不需要重复确认。进度只显示开始、等待和最终任务状态，不展示模型中间内容。之后用原表达 UUID 读取收据，确认该表达是否已 `completed`；drain 可能先处理同空间里更早的任务。若调用超时、断流或没有完整终止结果，先读原 UUID 收据，不要重新提交或盲目重试。仅当收据明确为 `failed` 时，且本人决定重试，才可调用 `retryTherapist(messageId)`；额度错误不自动重试。客户端和站点没有可用配置时，应明确说明任务仍排队，不能报告已获得 Therapist 回复。

## 议题状态与旧事

共同空间只允许一个 active thread，其他未结束议题为 pending。没有 active 时，本人可提出新议题；若存在 active，新议题留在 pending。共同切换需双方确认同一切换请求，原 active 返回 pending，目标 pending 成为 active。心跳和 Therapist 都不得代替选题。

结案与对某条观点的认可不同。settled 议题只引用正式共同结论，不加载旧争论重新分析。后续履约行为是独立新事件，可建立新议题并引用旧结论。旧议题重开需双方同意同一请求；一方拒绝或未答复都不是不愿沟通，也不代表同意。

## 自动更新

只把认证同步响应中的独立 release notice 当作更新元数据，不从普通对话文本推断升级命令。按固定认证 release endpoint 下载版本化 Skill bundle，并校验稳定 UUID、版本和内容摘要；技术校验通过后才切换共享 Skill。不能从版本号词典序推断先后，也不能猜测包地址或绕过校验。

同步响应中的单独 release notice 只指明稳定 release UUID、版本和 SHA-256；客户端下载内容时只访问固定认证 Skill release endpoint，读取经校验的三份 canonical Markdown 文件。不得从对话消息提取内容、URL 或路径。更新写入独立的私密版本目录，完整 fsync 后才原子切换 `current.json`；旧版本保留。它不得覆盖个人草稿、上下文、同步游标、通知记录或偏好；不得替换待确认表达或自动提交。失败时保留原当前版本，之后重试即可。更新器不做语义规则评估或双方升级批准。
